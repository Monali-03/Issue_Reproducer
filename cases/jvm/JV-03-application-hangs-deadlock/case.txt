## Topology
A batch processing service with a fixed thread pool of 16 workers. Each task takes two
locks: an account lock and a ledger lock. The order in which they are taken depends on
which side of the transfer is processed first.

## Configuration
JVM flags are in configs/jvm-args.txt. Nothing unusual: 1g heap, default collector.

## Steps to reproduce
1. Submit a batch containing transfers in both directions between the same two accounts.
2. Wait.

## Expected behavior
The batch completes.

## Actual behavior
The process stops making progress. CPU drops to zero, the process stays alive, and no
work completes. jstack reports a Java-level deadlock. Only a restart clears it.
