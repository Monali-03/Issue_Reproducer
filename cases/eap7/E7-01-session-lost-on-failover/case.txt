Case:               04003001
Product:            Red Hat JBoss EAP
Version:            7.4.0 (GA)
JDK:                Red Hat build of OpenJDK 11.0.22
OS:                 RHEL 8.9
Architecture:       x86_64
Deployment:         zip
Mode:               standalone
Platform:           VM
Nodes:              2 nodes, 10.8.14.21 and 10.8.14.22

## Topology
Two EAP 7.4 standalone-ha instances behind mod_cluster / httpd. Sticky sessions are on.
Both nodes are in the same subnet and use the shipped udp stack.

## Configuration
standalone-ha.xml, stock apart from the web cache container. The relevant block and the
application's web.xml are in configs/.

## Steps to reproduce
1. Log in on node1 through the load balancer; the session is created.
2. Kill node1 (kill -9 on the java process).
3. The next request is routed to node2.

## Expected behavior
The session continues on node2 and the user stays logged in.

## Actual behavior
The user is logged out — node2 issues a brand new JSESSIONID and the cart is empty.

## Error messages
No error is logged on either node. node2 simply creates a new session.

## Frequency
always

## What the customer has already tried
Confirmed sticky sessions are working (the route suffix changes only after the kill).
Confirmed both nodes log the same ISPN000094 view with 2 members before the kill.
